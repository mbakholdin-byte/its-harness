# Alex Review Loop — review-критик результата

## Назначение

Проверка и критика результата выполненной задачи перед показом Марку. Отдельная роль
«независимый критик»: свежий взгляд на результат, фиксация замечаний в **файле вердикта**, исправление
по замечаниям.

## Триггеры review

- `#review` явно в запросе Марка
- Задача затрагивает >= 3 файлов
- Генерация требований (ФТ/НФТ/ТИ/ОТ)
- Критические изменения конфигурации

## Алгоритм review (3 прохода)

1. **Pass 1 — Выполнение:** выполнить задачу как обычно (по плану оркестратора).
2. **Pass 2 — Критика:** запустить **свежего изолированного субагента** (роль `verifier`).
   На вход: исходная задача дословно / результат исполнителя / источники, на которые
   опирался исполнитель. Инструкция критику — verbatim из `VERIFIER_PASS` §5
   (см. `skills/agent-dispatch/SKILL.md` §5).
   Результат критика оформляется файлом `ИМЯ_АРТЕФАКТА.verdict.md` по канону
   `skills/verdict-file/SKILL.md`: первая строка `verdict: PASS|FAIL|ESCALATE`.
3. **Pass 3 — Исправление:** внести исправления по замечаниям из verdict-файла.

## Enforcement

- Максимум 2 прохода review (pass 2 + pass 3)
- Если после pass 3 остались замечания → остановить и сообщить Марку
- Не бесконечный цикл — жёсткий лимит
- Формат вердикта проверяется скриптом: `python scripts/verdict_gate.py ФАЙЛ` (exit 0/1).
  PASS ставит только скрипт.

## Зоны записи

- Независимый критик пишет **только** файл вердикта.
- Оркестратор вносит исправления по замечаниям и **не пишет** в файл вердикта ни строки.

## Формат REVIEW.md / verdict-файла

```markdown
verdict: PASS | FAIL | ESCALATE

# Verdict: НАЗВАНИЕ_ЗАДАЧИ
**Дата:** YYYY-MM-DD · **Проверяющий:** verifier · **Проход:** review-loop

## Проверял
- ЧТО_РЕАЛЬНО_ОТКРЫТО_ИЛИ_ВЫПОЛНЕНО

## Не сошлось
1. severity: blocker|major|minor · area: ФАЙЛ_ИЛИ_СЕКЦИЯ · claim: ЧТО_НЕ_ТАК · evidence: ИСТОЧНИК

## Не проверял
- ЧТО_ОСТАЛОСЬ_ЗА_РАМКАМИ_И_ПОЧЕМУ
```

Историческое имя `REVIEW.md` допустимо — формат тот же.

> Обозначения плейсхолдеров записаны в верхнем регистре вместо угловых скобок канона —
> гейт `verify_gate.py` считает угловые скобки незаполненными плейсхолдерами и поднимает
> FAIL на исходниках. Смысл полей идентичен канону.

## Результат (verdict)

По завершении вернуть вызывающему агенту:
- путь к verdict-файлу
- verdict: `PASS` (замечаний нет / все исправлены) или `FAIL` (остались замечания после pass 3 — эскалация Марку)

## Связанные каноны

- `skills/verdict-file/SKILL.md` — формат файла вердикта и зоны записи
- `skills/agent-dispatch/SKILL.md` — когда критика обязательна и как вызвать свежего критика
- `КАТАЛОГ_КАНОНОВ\VERIFIER_PASS.md` — семантика проверки (что именно ловит критик)
