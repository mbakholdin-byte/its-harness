# Deep Research — точный поиск с верификацией

## Обзор

Точность достигается процессом, а не движком: fan-out по нескольким поисковикам → полное чтение первоисточников (не сниппеты) → каждый ключевой факт подтверждён ≥2 независимыми источниками → отчёт с цитатами, датами и уровнем доверия.

## Когда использовать

- Важная информация, где цена ошибки высока (нормативы, даты, цены, версии API, чужие обязательства).
- Фактчекинг утверждения из переписки/статьи.
- НЕ использовать для: прогноза погоды, одноразовых любопытных вопросов, поиска по нашим базам (это RAG/память).

## Пайплайн (5 фаз, последовательно)

### Фаза 1 — Формализация
Inputs: вопрос пользователя. Outputs: research_brief.
- Зафиксировать, что именно считается точным ответом (критерий приёмки).
- Якорь даты: взять текущую дату из окружения (`date`), указать в отчёте.
- Составить 2–4 подзапроса (RU + EN формулировки).
- Вопрос про покупку/цену/доступность — обязателен локализованный подзапрос (город/страна пользователя, местные магазины и маркетплейсы), иначе ответ будет «по миру», а не «для пользователя».

### Фаза 2 — Fan-out поиск
Inputs: research_brief. Outputs: candidates[] (URL + сниппет + движок).
- Параллельно: `WebSearch` + `brave_web_search` (registry_execute resource="brave-search") + `tavily_search` (search_depth="advanced"; при свежести — time_range="week"/"month").
- Минимум 2 движка обязательно; недоступный движок — записать в отчёт («покрытие снижено»).
- Дедуп по URL/домену. Один endpoint+params — один раз за сессию.

### Фаза 3 — Чтение первоисточников
Inputs: candidates[]. Outputs: sources[] (полный текст + дата публикации).
- Топ 5–8 URL читать ЦЕЛИКОМ: `webclaw scrape` (формат markdown) — основной; fallback `FetchURL`.
- Приоритет: официальная документация/реестры/первоисточник > СМИ > агрегаторы/блоги-пересказы.
- JS-динамика или логин — kimi-webbridge. Paywall/логин-стена — зафиксировать, не считать источником.

### Фаза 4 — Верификация
Inputs: sources[]. Outputs: verified_facts[].
- Факт подтверждён, только если ≥2 независимых источника (не перепосты друг друга) сходятся.
- Расхождения — не усреднять, а показать оба значения с источниками.
- Отделять факт от мнения; у каждого факта — дата источника («на дату Х»).
- Запрещено цитировать источник, который не был прочитан полностью. Сниппет ≠ факт.

### Фаза 5 — Отчёт
Inputs: verified_facts[]. Outputs: research_report.
- Структура: краткий ответ → таблица фактов (утверждение | цитата | источники) → таблица источников (URL | дата | тип | доверие) → неподтверждённое/расхождения → confidence (высокий/средний/низкий + почему).
- Ссылки — полные URL. По запросу — сохранить в блокнот (skills `notebook`).

## Распространённые ошибки

- Ответ по сниппетам выдачи без чтения страниц → всегда фаза 3.
- «Все источники сходятся», но это перепосты одного → проверять независимость.
- Свежий вопрос без time_range → якорь даты + фильтр свежести.
- Движок молчит → тихо пропустить нельзя, фиксируем в отчёте.

## Зависимости

- MCP: `webclaw` (через mcp-fas-proxy; search/research требуют WEBCLAW_API_KEY, scrape — без ключа)
- MCP: `tavily` (прямой HTTP, env TAVILY_API_KEY; есть tavily_research — deep-research эндпоинт для сверки)
- MCP: `brave-search` (через mcp-fas-proxy, env BRAVE_API_KEY)
- Встроенные: WebSearch, FetchURL; плагин kimi-webbridge для сайтов с логином
- Health: registry_execute(resource="mcp-fas-proxy" не нужен) — при отказе движка работаем с оставшимися, фиксируя снижение покрытия
