# Auto-Verify: Автоверификация результата

## Назначение

После завершения нетривиальной задачи автоматически проверить результат перед показом пользователю. Ловит глупые ошибки: битые файлы, отсутствующие артефакты, regression, некорректный синтаксис.

**Отличие от self-correction:** self-correction — детекция петель и переключение стратегии. auto-verify — проверка качества результата перед сдачей.

## Когда активировать

| Критерий | Активировать | Пропустить |
|----------|--------------|------------|
| Файлов изменено | 3+ | 1-2 |
| Конфиги | Всегда | — |
| Кодогенерация | Всегда | — |
| Пользователь сказал «быстро» | Нет | Да |
| Пользователь сказал «кратко» | Нет | Да |

**Уровни проверки:**

- **Уровень 1 (Базовый):** Всегда при 3+ файлах
- **Уровень 2 (Стандартный):** Конфиги и код
- **Уровень 3 (Глубокий):** Только при явном запросе или сложной задаче

## Алгоритм

### Уровень 1 — Базовый (ВСЕГДА при 3+ файлах)

1. Проверить существование всех заявленных файлов
2. Проверить, что файлы не пустые (размер > 0 байт)
3. Проверить отсутствие очевидных артефактов записи:
   - `null`, `undefined`, `[object Object]` как значения
   - Обрезанные строки в середине JSON
   - Плейсхолдеры `{TODO}`, `{FIXME}`, `{TBD}`

### Уровень 2 — Стандартный (конфиги и код)

1. **JSON/YAML/TOML:** Парсинг без ошибок
   ```python
   import json
   json.load(open('file.json'))  # OK = PASS
   ```
2. **Python:** Синтаксис проверен
   ```python
   import ast
   ast.parse(open('file.py').read())  # OK = PASS
   ```
3. **PowerShell:** Проверка синтаксиса
   ```powershell
   powershell -NoProfile -Command "Get-Command -Syntax file.ps1"
   ```
4. **Config-файлы:** Ключи не перепутаны, пути валидны, строки не обрезаны

### Уровень 3 — Глубокий (только при явном запросе)

1. Тесты проходят (если есть тесты)
2. Нет regression — не сломано то, что работало
3. MCP-сервер отвечает после изменения конфига
4. Зависимости установлены (import, require)

## Формат вывода

```
Verify: 7/8 проверок пройдено
FAIL:
- config.json: строка 42 обрезана (ожидалось "...", получено "...")
- test_api.py: синтаксическая ошибка в строке 15
```

Если все PASS — краткая строка: `✓ Verify: 8/8 пройдено`

## Антипаттерны

- **НЕ** запускать верификацию для тривиальных правок (1-2 строки в одном файле)
- **НЕ** блокировать пользователя — если Марк ждёт ответ, показать результат, потом верифицировать в фоне
- **НЕ** дублировать проверки инструментов (write tool уже проверил существование)
- **НЕ** запускать Level 3 без явного запроса — это дорого по времени

## Пример из работы

**Задача:** Изменён opencode.json + создано 3 новых файла правил

```
Verify: 5/5 проверок пройдено
✓ opencode.json: валидный JSON, ключ environment → OK
✓ rules/BASH_RULES.md: существует, не пустой
✓ rules/MEMORY.md: существует, не пустой
✓ rules/SAFETY.md: существует, без плейсхолдеров
✓ DECISIONS.md: обновлён, нет артефактов записи
```

## Независимая верификация через bgagent (Verification Sub-Agent pattern)

После исправления ошибки в ходе самокоррекции (особенно если это был 2-й подход):
- Предложи запустить **Max для независимой верификации** через `bgagent_task`
- Max получает чистый контекст: описание задачи + изменённые файлы
- Max НЕ знает, какие ошибки были и как исправлялись
- Формат вердикта Max: `VERDICT (PASS/FAIL)` + детализация
- Если Max → FAIL: переключить стратегию ещё раз (вернуться к self-correction)
- Если Max → PASS: продолжить работу

Это гарантирует, что «исправление» действительно работает, а не просто перестало выдавать ошибку.

## Чек-лист перед сдачей результата

- [ ] Все файлы существуют
- [ ] Нет null/undefined/[object Object]
- [ ] JSON/YAML парсится
- [ ] Код компилируется/исполняется
- [ ] Нет regression в соседних модулях
