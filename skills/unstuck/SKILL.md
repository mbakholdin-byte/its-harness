# Unstuck: Выход из тупика

## Назначение

Расширение self-correction. Если самокоррекция сработала (СТОП + ДИАГНОЗ), но новая стратегия тоже провалилась — unstuck предлагает набор конкретных стратегий выхода.

**Отличие от self-correction:** self-correction = первая смена стратегии. unstuck = продолжение, если первая смена не помогла после 2+ попыток.

## Когда активировать

| Сигнал | Действие |
|--------|----------|
| self-correction сработала, результат снова FAIL | Перейти в unstuck |
| Провалено 2+ разных подхода | Перейти в unstuck |
| Пользователь: «ты застрял», «это не работает» | Перейти в unstuck |
| Сессия делает круг 2+ раза | Перейти в unstuck |
| Агент собирается повторить уже озвученный план | Перейти в unstuck |

## Стратегии выхода (по приоритету)

### 1. Уменьшить scope (приоритет: высокий)

Разделить задачу на минимальный воспроизводимый кейс.

**Формулировка:** «У меня не получается X. Предлагаю начать с минимального кейса — только A, без B и C. Потом добавим остальное».

**Когда:** Задача большая, непонятно где точно ломается.

### 2. Сменить инструмент (приоритет: высокий)

Другой язык, другой MCP-сервер, другой API endpoint.

**Примеры:**
- Python + requests не работает → попробовать curl
- MCP-сервер A не отвечает → использовать MCP-сервер B
- REST API endpoint /v1 → попробовать /v2

### 3. Спросить Марка (приоритет: средний)

Явный вопрос с вариантами ответа.

**Формулировка:** «У меня не получается X. Вижу два варианта: A и B. Что предпочтёте?»

**Когда:** Есть несколько равнозначных путей, непонятно какой правильный.

### 4. Откатить и начать заново (приоритет: средний)

Если текущее состояние хуже начального.

**Признак:** `git status` показывает много изменений, ничего не работает, исходное состояние утрачено.

### 5. Делегировать субагенту (приоритет: средний)

Запустить bgagent_task с чистым контекстом.

**Формулировка:** «Передаю этот подзадачу отдельному агенту с чистым контекстом для независимой оценки».

### 6. Пропустить и вернуться (приоритет: низкий)

Если задача не блокирующая.

**Формулировка:** «Проблема X пока не решена, двигаюсь дальше. Вернусь позже».

**Когда:** Задача важная, но не блокирует следующие шаги.

### 7. Запросить помощь от Марка (приоритет: низкий)

Предложить выполнить часть вручную.

**Формулировка:** «Не могу автоматизировать X. Можете выполнить этот шаг вручную, а я продолжу с результатом?»

## Алгоритм

### Шаг 1 — Оценка глубины тупика

1. Посчитать количество проваленных подходов
2. Определить, на каком этапе произошёл сбой ( Plan → Execution → Verify)
3. Записать текущее состояние в hmem

### Шаг 2 — Выбор стратегии

Применить стратегии в порядке приоритета. Если стратегия 1 не подходит — перейти к 2, и так далее.

### Шаг 3 — Явное объявление

Сказать пользователю: «Выбираю стратегию: [название]. Суть: [кратко]. Начинаю.»

### Шаг 4 — Эскаляция

Если провалились 3 стратегии из 7 — остановиться, показать сводку:

```
Тупик после 3 стратегий:
- Подход 1: FAIL (причина)
- Подход 2: FAIL (причина)  
- Подход 3: FAIL (причина)

Сводка: [краткое описание проблемы]
Рекомендация: [что сделать Марку]
```

## Пример из работы

**Ситуация:** Агент пытается подключиться к Qdrant через Python-клиент. Проблема: Windows + Unicode в пути.

1. **self-correction** сработала: «Попробую qdrant-client вместо requests»
2. **Результат:** та же ошибка
3. **unstuck активирован:**
   - Стратегия 1 (уменьшить scope): «Давайте сначала протестируем подключение к Qdrant через curl REST API, без Python»
   - **Результат:** curl работает
   - **Вывод:** проблема в qdrant-client на Windows

## Антипаттерны

- **НЕ** повторять тот же подход с другими параметрами (это не смена стратегии)
- **НЕ** игнорировать сигналы тупика — лучше раньше признать проблему
- **НЕ** доходить до 4+ стратегий без остановки — после 3-й пора эскалировать
- **НЕ** делать вид, что всё работает, если это не так

## Связь с self-correction

```
self-correction:
  СТОП → ДИАГНОЗ → СМЕНА_СТРАТЕГИИ_№1

unstuck:
  СМЕНА_СТРАТЕГИИ_№2 → ... → СМЕНА_СТРАТЕГИИ№7 → ЭСКАЛЯЦИЯ
```

## Чек-лист при активации unstuck

- [ ] Посчитано: сколько подходов уже провалено
- [ ] Выбрана стратегия из списка (по приоритету)
- [ ] Стратегия явно названа пользователю
- [ ] После 3-й стратегии — эскаляция, не продолжать
